📄 OS_Port/os_port.s — PendSV 上下文切换

STM32 ARMCCRP2040 GNU GAS
 
STMDB R0!, {R4-R11}
LDMIA R0!, {R4-R11}
LDR LR, =0xFFFFFFFD
BX LR
 
.global PendSV_Handler
.global isr_pendsv
/* R0 -= 16(累计 SUBS) */
subs r0, r0, #7 × 4
subs r0, r0, #4
stmia r0!, { r4-r7 }
mov r4, r8   /* high-bank 转 low */
stmia r0!, { r4-r7 }
ldmia r0!, { r4-r7 }
mov r8, r4
ldmia r0!, { r4-r7 }
push { r1 }  /* EXC_RETURN */
pop { pc }

M0+ vs M3 关键差异

用法M3M0+ 限制移植方案
STMDB R0!, {R4-R11}✓不存在 STMDB累计 SUBS + 两条 STMIA
SUBS R0, #32✓SUB imm3 仅 0..77×4+4 累加
STR R8, [R0, #16]✓STR Rt 仅 r0-r7MOV R4, R8 + STMIA
LDMIA R0!, {R4-R11}✓不能跨寄存器组拆为 {R4-R7} + {R8-R11}
BX LR 触发 EXC_RETURN✓GAS width suffixpush {r1}; pop {pc}

🔧 CPU 占用率验证(spin_task 测试)

为了验证 os_idle_max 是否合理,临时加一个 spin_task (prio 1,纯空转不调 os_delay):

----- 加 spin_task 后 -----
SPIN |  RUN |  01  | 016 / 256    ← 抢占 idle
IDLE |  RDY  |  00  | 016 / 128    ← 几乎不跑
========================================================
CPU Usage: 100%   ← idle 满被抢,完美吻合 idle_max = 15000000
========================================================

结论:spin_task 让 idle 完全被抢占,idle_count ≈ 0,usage = 100 - 0 = 100%。**说明 os_idle_max = 15000000 接近实际值**(理论 15.6M/s,估算偏差 < 4%)。

🐛 踩坑记录(9 个)

症状原因修复
LED 不闪,程序卡住 SDK 默认 weak isr_pendsv 是 BKPT;GNU ld 把 SDK weak 抢先于我们的 strong 汇编加 .global isr_pendsv;CMakeLists 用 --whole-archive minirtos
printf 多任务卡死 USB CDC 默认阻塞 500ms 等 DTR PICO_STDIO_USB_STDOUT_TIMEOUT_US=1000
CPU Usage = 101% INFO 任务栈 512 word 被 printf vsnprintf 嵌套栈溢出 INFO 栈加大到 1024 word
CPU Usage 一直 0% 空闲 idle_count 远超 idle_max,wraparound;WFI 让 idle 暂停,校准分母太小 idle_task 改空转 + 主程序 busy_wait 估算 idle_max
M0+ SUB #16/#32 报错 M0+ SUB 立即数 imm3 仅 0..7 多次 SUBS 累加
R8-R11 不能直接 STR M0+ STR Rt 仅支持 r0-r7(3 位编码) MOV R4, R8 暂存到 low-bank 再 STMIA
bx lr 触发 EXC_RETURN 失败 GAS 把 lr,=imm 误判为 width suffix 改用 push {r1}; pop {pc}(SDK 已验证 16 位合法)
CALIB 任务自我删除后还在 RDY CALIB 在 os_sched_init 阶段还没启动,RTOS 没真正校准 改用主程序 busy_wait 估算 idle_max(15000000)
os_delay 改小后 INFO 卡死 INFO 栈 384 word 不够 + 高频 os_system_info INFO 栈固定 1024 word,os_delay 改回 5000

🎯 总结经验教训

  1. RP2040 工具链陷阱:GNU AS + M0+ 的 SUB/ADD 立即数范围只有 0..7
  2. Pico SDK vector table 用 isr_* 名字:必须同时导出 Pend_S_H + isr_pend,否则 weak BKPT 抢占
  3. SDK 默认 weak handler 是 BKPT:如果用户实现没真正链接进 vector table,异常触发 → 死锁
  4. GNU ld 静态库按需加载:--whole-archive 强制整体链接
  5. printf 阻塞陷阱:USB CDC 未连接时阻塞输出,RTOS 任务卡死
  6. 栈溢出破坏 TCB:printf 嵌套 vsnprintf 栈深度大,INFO 任务必须用大栈(1024 word)
  7. CPU% 校准:WFI 让 idle 暂停导致校准失败,改成空转累加 idle_count
  8. change task 行为要相应改栈:高频调用 printf 必须加大栈
