# 2026-09-18

## 分析 app_dap.c(用户重写版)PIO 探测缺失 —— 只讲解方案,未改任何源码

用户明确要求「不可以直接修改,教我怎么完善」,且他已自行重写了
`app/app_dap.c`(12KB,上一轮那套 tab/pin_config/dropdown/独立 pio_swd 实例全被删掉)
和 `app/cmsis_dap.c`。

### 用户改动后的当前状态
- `cmsis_dap.c:33` `g_dap_enabled = true`(从 `false` 改成 `true`,加了注释说明"上电即响应 HID")
- `cmsis_dap.c:35` `g_dap_cur_clock_hz = 5000000`(5MHz)
- `app_dap.c` 新版 `on_probe_click` 只做两件事:
  `data->target_detected = true; g_dap_enabled = !g_dap_enabled;`
  —— 没有 PIO 调用、没有引脚初始化、没有 `usb_switch_mode`;
  `#include "fun_pio_swd.h"` 还在但**零个函数被调用**
- `dap_enter()` 里上一轮加的 `if (g_dap_enabled) usb_switch_mode(0);` 被删掉了
- `dap_exit()` / `dap_update()` 都是空实现
- `dap_data_t` 里只有 `target_detected`,没有 dp_id / cpuid / flash 字段
  → draw 里会画出 ID / CPU ID / FLASH SIZE 三个空标签

### 关键架构事实(核心结论,必须记住)
**PIO SWD 实例的所有权在 `cmsis_dap.c`,不在 App。**
- `cmsis_dap.c:57` `static fun_pio_swd_t s_pio_swd;`
- `cmsis_dap.c:180-193` 第一笔 DAP 传输时懒加载
  `fun_pio_swd_open_session(..., line_reset=false)`
  (注释:Keil 已通过 SWJ_Sequence 建立会话,不再复位目标)
- `cmsis_dap.c:62` `cmsis_dap_set_backend()` 里 `fun_pio_swd_close()`
- **App 拿不到这个实例**

→ App 若自己再 `fun_pio_swd_open_auto/open_session`,有三个后果:
1. 抢第二个 PIO SM(浪费,且可能抢不到)
2. **同一对 GPIO 被两个 PIO SM 同时驱动** —— `open_session` 内部有 `pio_gpio_init` +
   `pio_sm_set_pindirs_with_mask` 把两脚全设成输出 → 信号打架,DAP 直接通信失败
3. `open_auto` 的 `line_reset=true` 会发 5 次 line reset + JTAG-to-SWD 序列(0xE79E),
   **打断 Keil 已建立的会话**
→ 所以正确做法是让 `cmsis_dap.c` 暴露 API,App 只调 API。

### 给用户的方案(已讲解,未落地)
`cmsis_dap.h/.c` 新增:
- `uint32_t cmsis_dap_get_clock_hz(void);` — 让 UI 显示真实生效频率
- `bool cmsis_dap_pio_open_now(bool line_reset);` — App 探测传 `true`,DAP 命令路径传 `false`
- `bool cmsis_dap_probe_target(uint32_t *dp_id, uint32_t *cpuid, uint32_t *flash_kb);`
  内部链路:`fun_pio_swd_read_dp_idcode`(DP 0x00)→ `fun_pio_swd_power_up`
  → `fun_pio_swd_read_memory32(0xE000ED00)` 取 CPUID
  → `fun_pio_swd_read_memory32(0x1FFFF7E0) & 0xFFFF` 取 Flash KB

`app_dap.c` 的 `on_probe_click` 应走五步:
`usb_switch_mode(0)` → `g_dap_enabled = true`(不是取反)→ `cmsis_dap_pio_open_now(true)`
→ `cmsis_dap_probe_target(...)` → 刷 `dirty_rect`。
`dap_data_t` 要补 `dp_id / cpuid / flash_kb / pio_ok` 字段。
建议 `dap_exit` 里释放 PIO(`cmsis_dap_set_backend(CMSIS_DAP_BACKEND_SOFTWARE)` 即可,
它内部会 close),否则离开 App 后 PIO SM 一直被占,其他 PIO 功能(如 fun_pio_uart)会抢不到。

### 另外两个真实脱节(已提醒用户)
1. **时钟脱节**:`fun_swd_config.c` 默认 `clock_hz = 10000000`(10MHz),
   而 DAP 后端用 `g_dap_cur_clock_hz = 5000000`(5MHz)。
   `fun_swd_config_set_clock()` 全工程无人调用。
   `g_dap_cur_clock_hz` 只在收到 `ID_DAP_SWJ_Clock` 命令时更新(`cmsis_dap.c:434` 附近)。
   → 状态页显示 10MHz 但实际跑 5MHz,应改用 `cmsis_dap_get_clock_hz()`。
2. **pin_manager 未登记**:`fun_pio_swd_open_session` 只向 `pio_manager` 申领 SM,
   没有调 `pin_manager_claim` → GP2/GP3 被 PIO 占了但 pin_manager 里仍显示空闲,
   其他功能可能误判这两脚可用。

### 环境备注
- `fun_swd_config.c` 默认引脚:SWCLK = GP2,SWDIO = GP3。
- 用户口中的「PIO SWO」实际指 PIO SWD(项目里没有 SWO trace 相关代码)。
